## 2. 启动与任务结构

复位从 `0x0070` 开始，已按指令核对：

1. 清 XDATA `0x8000-0x97FF`（24 × 256 字节）。
2. `SP = 0xC0`。
3. 写 `0x1001 = 0x3F`。
4. 依次调用 `0x280A`、`0x2D41`、`0x23E4`、`0x2D46`、`0x5864`。
5. 跳转 `0x0112`。

中断向量：

| 向量 | 目标 |
|---|---|
| `0x0000` | `0x0070` |
| `0x0003` | `0x0538` |
| `0x000B` | `0x0539` |
| `0x0013` | `0x056F` |
| `0x001B` | `0x05D6` |
| `0x0023` | `0x05FE` |
| `0x002B` | `0x05FF` |

`0x0070` 清内存后跳到 `0x0112`，后者从 code `0x7178` 读表解释执行；具体语义未还原。

bank0 `0xA170-0xA1AF` 是一组任务入口，其中 `0xA17F` 是电池任务，内部调用 `0x40F9` 后跳 `0x580A`。任务调度器本身未定位，这些入口的 `callers` 为 0，说明通过跳转表或函数指针到达。

## 3. 电池管理

### 3.1 状态寄存器

| 名称 | 地址 | 依据 |
|---|---|---|
| `BAT_REG_ERRCOUNT` | `0x0693` | 每次命令失败递增，`0x43B2` |
| `BAT_REG_MAILBOX` | `0x069D` | 通知描述符 `{id, addr_hi, addr_lo, 0}` |
| `BAT_REG_STATE` | `0x8998` | bit0 表示初始化完成 |
| `BAT_REG_MODEL_SRC` | `0x898A` | 型号选择输入 |
| `BAT_REG_CMD` / `ARG` | `0x89A4` / `0x89A5` | 命令 `0x8B` 与参数 `0x28`/`0x2C` |
| `BAT_REG_MODEL` | `0x89A6` | 型号，取值 `0x14` / `0x16` |
| `BAT_REG_SYNC` | `0x89A7` | 写型号后固定写 `0x08` |
| `BAT_REG_CHG_READ_HI/LO` | `0x89CB` / `0x89CC` | 与设定值比较的读回值 |
| `BAT_REG_CHG_SET_HI/LO` | `0x89D2` / `0x89D3` | 充电电流设定值 `0xD4`/`0x05` |
| `BAT_REG_LAST` | `0x89D6` | 保存本次错误计数 |
| `BAT_REG_CFG_A` | `0x83C0` | bit5 挂起电池任务；非 0 时跳过型号选择 |
| `BAT_REG_CFG_B` | `0x83C3` | bit4 挂起电池任务 |
| `BAT_REG_CFG_C` | `0x83F0` | bit0 选择型号分支 |
| `BAT_REG_TIMER` | `0x847C` | 与 `0x1E` 比较，决定刷新参数 |
| `BAT_REG_STAGE` | `0x1603` | bit3 选择电压阶段 |
| `BAT_REG_STAGE_A/B` | `0x837A` / `0x837B` | 阶段值 `{0x80,0x0D}` 或 `{0x00,0x0B}` |
| `BAT_REG_PARAM_A..D` | `0x89CD`/`CE`/`D0`/`D1` | 两组 `{0x00,0x0F}` |

`0x89CB/CC` 的“读回”、`0x89D2/D3` 的“设定值”是根据比较和写入关系命名的，单位未在硬件上确认。

### 3.3 行为

初始化序列：

1. `0x0693 = 0`。
2. 发送命令 `0x8B/0x28`，通知 `0x3D→0x89A4`。
3. 写型号 `0x14`，同步 `0x08`，通知 `0x3B→0x89A6`。
4. 写充电设定 `0xD4/0x05`，通知 `0x3C→0x89D2`。
5. 按 `0x1603 bit3` 写阶段值，通知 `0x3F→0x837A`。
6. 写参数 A 组，通知 `0x16→0x89CD`。
7. 写参数 C 组，通知 `0x17→0x89D0`。
8. `0x89D6 = 0x0693`；错误计数为 0 时置 `0x8998 bit0`。

前 6 次命令失败都会使 `0x0693` 递增；周期任务里的刷新和型号选择不计数。

周期任务：

1. `0x83C0 bit5` 或 `0x83C3 bit4` 置位时直接返回。
2. `0x8998 bit0` 未置位时执行初始化序列。
3. `0x847C < 0x1E` 时确保命令为 `0x8B/0x28`，否则确保为 `0x8B/0x2C`；后者会同时把 `0x89A6` 清 0。
4. `0x89CB/CC` 与 `0xD4/0x05` 不一致时重写 `0x89D2/D3` 并通知 `0x3C`。
5. `0x83C0` 非 0 或 `0x8998 bit0` 为 0 时返回，否则进入型号选择。
6. 型号选择：`0x83F0 bit0` 为 1 时目标型号 `0x14`，否则 `0x16`；只写与 `0x898A` 不同的值，然后同步 `0x08` 并通知 `0x3B`。

### 3.4 代码与测试

- 语义实现：`port/src/modules/ec_battery.c`
- 寄存器与命令常量：`include/ec_battery.h`
- 仿真测试：`tests/sim/battery_sim.c`、`tests/test_battery_sim.py`

测试用 SDCC 编译成 8051 程序，在 8051 模拟器（Windows `s51.exe` / Linux `ucsim_51`）里执行 11 个场景，记录寄存器快照和每次命令的 `{cmd, arg, notify, addr}`。覆盖：型号主/备分支、型号保留、两个挂起条件、初始化成功/失败、阶段两个分支、标准刷新、备用刷新、充电设定重写。

原模块与汇编的偏差已修正：

- 每次命令都清 `0x89A6`，实际只有 `0x8B/0x2C` 路径清。
- 漏掉 `0x8B/0x28` 的 `0x3D→0x89A4` 通知。
- 充电步骤多写 `0x89D4`，并漏掉 `0x3C→0x89D2` 通知。
- 初始化写型号时漏掉 `0x89A7=0x08`。
- 刷新阈值写成 `0x1F`，实际比较值是 `0x1E`。

### 3.5 C 固件集成

`python3 tools/build.py --firmware` 把语义 C 函数编入 128 KiB 镜像：

| 覆盖 | 原始入口 | C 源 | 入口 | 代码段 | 补丁 |
|---|---|---|---|---|---|
| 电池任务 | `0x40F9`（调用点 `0xA182`） | `ec_battery.c` | `0xE600` | `0xE600-0xE80F` | `12 40 F9` -> `12 E6 00` |
| 校验更新 | `0x203A` | `ec_crc.c` | `0x7B00` | `0x7B00-0x7B7C` | `78 AF E6` -> `02 7B 00` |

原始 `0x4061`/`0x40F9`/`0x203A` 的函数体保留在镜像里，但入口已被转发。集成镜像与参考镜像的差异只在两个 C 代码段和两个补丁点。

`tests/test_firmware.py` 在模拟器里：

- 从 `0xA182` 执行电池 C 任务（分发器替换为返回成功的桩），校验型号、邮箱、初始化序列和 bank0 恢复；初始化场景实测栈最深 `0xD2`。
- 从 `0x7C00` 的测试桩调用 `0x203A`，用 4 组输入校验 CRC 返回值和 IRAM `0xAF`。

限制：C 代码段使用寄存器组 0、`SP=0xC0` 的现有栈，没有实机验证中断并发；全量 C 翻译链接后 CSEG 为 268,877 字节，超过 8051 的 65,536 字节，不能作为固件。

### 3.6 命令层校验更新（`0x203A`）

- 输入：`R7` 一个字节。
- 状态：IRAM `0xAF`，按间接寻址访问。
- 输出：`R7` 返回移位后的值，同时更新 `0xAF`。
- 算法：两步位更新，第一步根据高位置 `0x09`，第二步根据高位置 `0x07`。
- C 实现：`port/src/modules/ec_crc.c`，`DSEG=0`。
- 包装：`src/glue/crc_hook.a51`，活动寄存器组为 0 时直接调用，否则保存/恢复 bank0。

测试向量（初始状态 `0x5A`）：

| 输入 | 返回 | 状态 |
|---|---|---|
| `0x00` | `0x68` | `0x81` |
| `0x01` | `0x6C` | `0x86` |
| `0x80` | `0x68` | `0x08` |
| `0xFF` | `0x4A` | `0x72` |

该函数被 `0x1A4C`、`0x1D49`、`0x1F70` 三个命令分发入口共用。

## 4. 命令与邮箱协议

已验证部分：

| 地址 | 作用 |
|---|---|
| `0x069A` | 状态 / 返回码 |
| `0x069B` | 命令字（调用约定 `R5`） |
| `0x069C` | 参数（调用约定 `R3`） |
| `0x069D-0x06A0` | 通知描述符：`{id, addr_hi, addr_lo, 0}` |
| `0x1A4C` | 分发表，20 个调用方 |

电池使用命令类 `0x8C`，操作码 `0x12`（通知）、`0x16`（参数写回）。`0x1A4C` 内部按 `0x069B` 分发，其余命令类的语义未整理。

## 6. 命名约定

- 汇编重建：`f_XXXX`（固定区）、`g_XXXX`（bank1）、`h_XXXX`（bank2）。
- 语义模块：`bat_*`、`ec_command_*`，对应关系写在本文件，不写进生成代码。
- 新模块放在 `port/src/modules/`，头文件放 `include/`，测试放 `tests/`。
